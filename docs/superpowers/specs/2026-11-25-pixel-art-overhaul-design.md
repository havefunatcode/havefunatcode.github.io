## 1. 의도 / 왜

지금 게임은 픽셀 게임의 형식은 갖췄지만 **에셋이 단조롭다**: 플레이어는 12x16 1프레임에 sin 1px 흔들림, 지면·발판·상자는 `fillRect` 도형, 배경 언덕은 반원 반복, 이펙트는 없다.
목표는 **「진짜 픽셀 게임처럼 느껴지는 것」**[사용자]. 그리고 **플레이어 캐릭터를 사용자 본인의 프로필 이미지 기반**으로 바꾼다[사용자].

### 성공 기준 (한 줄)
처음 본 사람이 「잘 만든 인디 픽셀 게임」이라고 느끼고, 플레이어가 본인(검은 옆가르마·동그란 안경·차콜 후드티)으로 알아보이며, 기존 성공 기준(누구나 막힘없이 PDF 도달)은 그대로 지켜진다.

## 2. 목표 / 비목표 / 반목표

**목표**
- 캔버스의 모든 시각 요소를 한 화풍(B)으로 다시 그린다: 플레이어·지면·발판·코인·보물상자·배경(하늘·해·별·구름·산·언덕·나무) [사용자: 범위 C].
- DOM 오버레이(타이틀 카드·HUD·상자 안내·토스트·상단 버튼·터치 버튼·favicon)도 화풍 B로 재테마한다 [사용자, §5.15].
- 플레이어 동작 애니메이션: 대기·걷기·점프 상승·낙하·착지.
- 이펙트: 코인 획득·착지 먼지·보물상자 열림.
- 보물상자 열림을 **짧게 보여준 뒤** 모달을 연다(§5.8) [사용자].

**비목표** (이번에 안 함)
- 레벨 구성·물리 상수·점프 감각·`resize()` 동작 변경(히트박스 높이만 조정, §5.2).
- 적·NPC·새 스테이지·사운드 교체·모달/PDF 구조 변경.
- 큰 초상화(48x48 등) — 후속 후보로만 남긴다.

**반목표** (기술적으로 돌아가도 실패로 본다)
- PDF 도달이 늦어지거나 막힌다(스킵 버튼 지연, 상자 연출 강제 대기).
- 첫 화면 로딩이 눈에 띄게 느려진다(이미지 프리로드 대기 등).
- 화풍이 요소마다 따로 논다(외곽선 규칙·팔레트 불일치, 이펙트의 팔레트 밖 색 포함).
- 캐릭터가 본인으로 안 보인다(머리·안경·후드티 중 하나라도 안 읽힘).
- reduced-motion 사용자에게 새 움직임이 강요된다.

## 5. 결정 사항

### 5.1 화풍 B — 「아늑한 인디」 [사용자: 브라우저 시안 3안 중 B]
- 차분한 채도. **검은 외곽선 금지** — 외곽선은 그 면의 가장 어두운 같은 계열 색(셀렉티브 아웃라인).
- 하늘은 4~5단 밴드 + 경계 2~4px 디더. 그라디언트 금지.
- 한 오브젝트당 3~4톤(어두움·기본·밝음·하이라이트). 광원은 좌상단 고정.
- 기준 색(시안 B, 빌더가 ±조정 가능):

|---|---|
| 하늘(새벽 기준 5단) | `#9fb8d8` `#b9c9dc` `#d8d6d8` `#efd8c8` `#f6e2cc` |
| 해 / 해 테두리 | `#fff1d0` / `#f8d8a8` |
| 구름 / 구름 그늘 | `#fbf3ea` / `#e2d6d0` |
| 먼 산 / 그늘 | `#a9a6c4` / `#8e8aae` |
| 먼 언덕 / 그늘 | `#a8c3b0` / `#8daa98` |
| 가까운 언덕 / 그늘 | `#7fa68c` / `#668d74` |
| 나무 줄기 / 잎 / 잎 밝음 / 잎 그늘 | `#8a6448` / `#6f9a6a` / `#94bd84` / `#557a56` |

- **시간대 연출 유지** [내 판단 — 수용 기준 8을 체감하게 하는 핵심이 해 이동과 별이라서]: 3키프레임(저녁 0 / 새벽 0.5 / 오전 1)이 바꾸는 것 = 하늘 5단·해 색·**해 위치(sunXr 0.15→0.5, sunY 124→50)·크기(30→22)**·**별(저녁에만, 진행할수록 사라짐)**·구름 색과 불투명도·산·언덕·**나무 색**. 위 표는 「새벽」. 저녁·오전 값은 같은 채도 규칙으로 만들고 M1 게이트에서 승인. 땅·발판·코인·상자·플레이어 팔레트는 시간대 불변(가독성).
- 시안 원본(`visual-style-v2.html`)은 세션 임시 폴더에 있으므로 `tools/art-src/mockups/`로 복사해 보존한다 [내 판단]. 시안과 이 문서가 충돌하면 **이 문서가 우선**.

### 5.2 플레이어
- **스프라이트 16x24**, **히트박스 12x20** [내 판단: 사진을 담으려면 키워야 하고, 발판 밑 최소 여유 22가 상한]. `makePlayer` `h: 16 → 20`. 레벨 주석(`level.js:5` 「점프 정점 ≈148」 → h20 기준 144)만 갱신.
- **그리기 앵커**(발 가운데 정렬): `drawX = round(x + w/2) - 8`, `drawY = round(y + h) - 24`. 좌측 반전은 `translate(drawX + 16, drawY)` → `scale(-1,1)` → `drawImage(frame, 0, 0)`. 두 분기 모두 같은 `drawY`를 쓴다(현행 `translate(x + w)` 그대로 두면 방향 전환 때 2px 튄다).
- **시점·반전** [내 판단]: 플랫포머 표준인 **3/4 측면**으로 그리고 좌향은 좌우 반전으로 만든다(옆가르마 방향이 반대가 되는 것 허용). M3 게이트에서 좌·우 두 방향을 함께 보여 승인받고, 반려되면 좌향 프레임을 따로 만든다(+프레임 수).
- **머리 위 여유** [내 판단]: 머리카락 4px은 히트박스 밖이라 x=880 발판 밑에서 2px가 발판과 겹칠 수 있다. **월드 그리기 순서를 「플레이어 → 지면·발판 타일」로 바꿔** 머리카락이 발판 뒤로 들어가 보이게 한다. 히트박스끼리는 겹치지 않으므로 다른 부작용이 없다(코인·상자·이펙트는 타일 뒤에 그려야 할 이유가 없어 순서: 배경 → 코인·상자 → 플레이어 → 타일 → 앞 이펙트).
- 외형(프로필 이미지 `~/Downloads/havefunatcode_profile.png`, 1024x1024 정면 흉상 일러스트): 검은 머리 옆가르마·오른쪽 볼륨, 동그란 짙은 회색 안경, 차콜 후드티(후드 깃 + 끈 2줄 — 원본 끈은 짙은 선이지만 16px 가독성을 위해 밝은 회색으로 [내 판단]), 진청 바지, 어두운 신발. 원본에 하반신이 없으므로 하반신은 새로 그린다.
- 팔레트(시안 B 기준): 외곽 `#2a2428` · 머리 `#26232a`/`#3e3a44` · 피부 `#f0c4a2`/`#d8a084` · 안경 `#56525a` · 입 `#b07060` · 후드 깃 `#383e3e` · 후드 `#4e5654`/`#3c4444` · 끈 `#a6aaa6` · 바지 `#454a62` · 신발 `#2e2a32`.
- 동작(프레임·속도):

| 상태 | 프레임 | 재생 | 진입 조건 |
|---|---|---|---|
| idle | 2 (숨쉬기 1px) | 0.5초 간격 반복 | 지면 + moveX=0 |
| walk | 6 | 10fps, 이동 중만 진행 | 지면 + moveX≠0 |
| jumpUp | 1 | 정지 | 공중 + vy<0 |
| fall | 1 | 정지 | 공중 + vy≥0 |
| land | 1 (찌그러짐) | 80ms 후 idle/walk | `touchdown` + `impactVy ≥ 200` (시작·리스폰 착지는 160대라 해당 없음) |

- reduced-motion이면 idle 숨쉬기 정지(1프레임 고정), walk는 유지(조작 피드백이므로 필수 모션), land는 유지(1프레임 80ms라 움직임 강요 아님) [내 판단].

### 5.3 지면·발판 타일
- 지면: **16x16 타일**. 윗면(잔디 끝 들쭉날쭉) / 왼끝 / 오른끝 / 흙 내부 2종 변형(위치 해시로 선택). 구덩이 경계는 끝 타일.
- 세그먼트 폭이 16의 배수가 아니므로(340·370·420) 오른끝 타일은 세그먼트 오른쪽에 정렬하고 중간을 잘라 그린다.
- 발판: 높이 14, **왼끝·중간·오른끝 3조각**(나무 판자, 위 하이라이트·아래 그늘·못 자국). 폭(56·60)에 맞춰 중간 반복 + 자름.

### 5.4 코인
- 8x8 유지(`COIN_SIZE`·히트박스 불변). **회전 6프레임**, 8fps. 상하 1.5px 흔들림 유지. reduced-motion이면 정면 1프레임 정지.
- 회전은 **모든 상태(title·play·opening·modal 뒤)에서** 돌도록 `Game.t`와 별개인 그리기 시계(`animT`, 매 프레임 증가)를 쓴다 [내 판단 — 지금은 play에서만 `t`가 흘러 타이틀에서 정지].

### 5.5 보물상자
- 히트박스 44x36 유지. 스프라이트 **32x28**을 하단 중앙에(`drawX = x + 6`, `drawY = y + 8`).
- 프레임: 닫힘 / 열림 1 / 열림 2 / 열림(빛 새어 나옴). 근접(`atChest`) 시 닫힘 상태에서 1px 반짝임 점멸(reduced-motion이면 정지).

### 5.6 배경 (레이어·패럴랙스)
- 레이어(뒤→앞): 하늘 밴드+디더 / 별 / 해 / 구름(스프라이트 3종) / 먼 산 / 먼 언덕 / 가까운 언덕 / 나무 줄(스프라이트 2~3종).
- 패럴랙스: 구름 0.2(+6px/s 표류, reduced면 정지), 먼 언덕 0.25, 가까운 언덕 0.45(이상 현행), 먼 산 0.1, 나무 줄 0.6(신규).
- 실루엣(산·언덕 능선)은 결정론적 함수(사인 합 또는 직접 구현한 시드 노이즈, 외부 라이브러리 없음). **반복 주기는 1100보다 길게** 잡고 화면 폭만큼 두 장을 이어 그린다 → 270~1100 전 구간 이음새 없음.
- 실루엣은 시작 시 **마스크 캔버스로 한 번 굽고**, 프레임마다 진행도 색으로 채색(방법은 빌더 재량). `resize`는 다시 굽지 않는다(현행과 같음). 1100x270에서 60fps 목표.

### 5.8 보물상자 열림 시퀀스
- 상태 추가: `'opening'` (`title | play | opening | modal`).
- **로직 위치** [내 판단 — Node 테스트 가능하게]: `Game.update` 안에서 처리. `state==='opening'`이면 early return 하지 않고 `openTimer += dt`, 상자 프레임·이펙트·`animT` 진행, 점프 엣지 감지. 진입·종료는 콜백으로 main.js에 알린다: `onOpening()` → `setState('opening')`, 종료 시 기존 `onTreasure()`. `setTimeout` 쓰지 않는다(스킵과 겹쳐 모달 이중 호출 방지).
- 흐름: 상자 근접 + 점프 엣지 → `opening`(이동 입력 무시, 플레이어 idle) → 상자 열림 프레임 + 반짝이 → **0.6초** 후 `onTreasure()` → 모달.
- 재입력: `opening` 중 점프 엣지(Space·↑·W·터치 점프)면 즉시 `onTreasure()`. Enter는 `main.js` keydown에 `st==='opening'` 분기를 추가해 같은 동작 [내 판단].
- 스킵 버튼: 어떤 상태에서든 즉시 모달(현행). `opening` 중이면 타이머를 취소한다(`onTreasure` 1회 보장).
- reduced-motion이면 `opening`을 건너뛰고 즉시 모달.
- `audio.treasure()`는 **`opening` 진입 시점**에 재생(보상감이 늦지 않게)하고, 모달 열 때 중복 재생하지 않는다 [내 판단].
- `chestOpened` 플래그 [내 판단]: `opening` 진입 때만 켠다(스킵으로 모달을 연 경우는 상자를 안 연 것). 이미 열린 상자 앞에서 다시 점프하면 `opening` 없이 즉시 모달. `reset()`에서 초기화. `drawChest`의 열림 판정을 `state==='modal'` → `chestOpened`로 바꾼다.
- `openTreasure`에서 `prevState`가 `'opening'`이면 `'play'`로 정규화(나중에 `setState(prevState)`로 바뀌어도 루프 방지).
- CSS: HUD·상자 안내·터치 컨트롤 셀렉터(`style.css:93,94,106,107,213`)에 `opening`을 추가해 0.6초 동안 사라지지 않게 한다(모바일 재입력 가능). 상자 안내 문구(`updateChestHint`)는 `opening`에서 숨긴다(현행 조건 유지).
- `engine.js:132` 상태 목록 주석, 디버그 훅 `__setState` 갱신.

## 6. 수용 기준
1. 선행 설계의 수용 기준 1~6이 그대로 통과한다(스킵 즉시 모달 포함).
2. 캔버스의 모든 요소와 DOM 오버레이가 화풍 B 규칙(검은 외곽선 없음·3~4톤·디더 하늘·이펙트 팔레트 일치·각진 픽셀 모서리)을 따른다 — 사용자 육안 승인. DOM 텍스트 대비 AA 이상.
3. 플레이어가 프로필 이미지의 머리·안경·후드티로 알아보인다(좌·우 방향 모두) — 사용자 육안 승인.
4. 대기·걷기·점프·낙하·착지가 상태에 맞게 재생되고, 방향 전환 시 캐릭터 위치가 튀지 않는다.
5. 코인 획득·착지·상자 열림 이펙트가 보이고, reduced-motion에서는 모두 꺼진다.
6. 상자 열림 0.6초 후 모달, 재입력(키보드·터치) 시 즉시, 스킵 버튼은 항상 즉시, 모달은 한 번만 열린다.
7. 가로 **270·480·1100** 세 폭에서 배경 이음새·빈틈이 없다.
8. 저녁→오전 시간대 전환(하늘색·해 상승·별 소멸)이 유지된다.
9. 외부 이미지·오디오 파일 0개, 빌드 없음, Node 테스트 전부 통과.
10. 예산(§5.13) 충족.

## 7. 진행 단계 (각 단계 끝에 사용자 승인 게이트)
- **M1 팔레트·배경**: `palette.js`·`background.js`, 시간대 3키프레임(270·480·1100 폭) 승인.
- **M2 타일·소품**: 지면·발판·코인·상자·구름·나무 + 그리기 순서 변경.
- **M3 플레이어**: codixel vs Pixelbolt 비교 시안(좌·우) → 선택 → 애니메이션 + 히트박스 20 + `anim.js` + `touchdown`.
- **M4 이펙트·상자 시퀀스**: pixelfx 원본 렌더 확인 → 변형 3종 + `opening` 상태 + CSS.
- **M5 DOM 재테마·마무리**: `style.css` 재테마(§5.15, 대비 측정)·favicon·CREDITS·예산 측정·세 폭·reduced-motion 확인·라이브 배포(`main` + `main:deploy`, 캐시버스터 curl 실측).
